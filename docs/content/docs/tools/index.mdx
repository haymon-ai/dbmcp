<Dbmcp /> exposes four tools through the MCP protocol. AI assistants call them to explore and query your database. Clients prefix the server name, so in Claude Code the tools appear as `mcp__dbmcp__objects`, `mcp__dbmcp__read`, and so on.

## Tool Availability

| Tool | Purpose | Annotations | Hidden when read-only |
|------|---------|-------------|-----------------------|
| [`objects`](/tools/objects) | List tables, views, triggers, functions, procedures, materialized views, or databases | `readOnlyHint` | No |
| [`read`](/tools/read) | Run a read-only `SELECT`, `SHOW`, `DESCRIBE`, or `EXPLAIN` | `readOnlyHint` | No |
| [`explain`](/tools/explain) | Show a statement's execution plan | `readOnlyHint` | No |
| [`write`](/tools/write) | Run data and schema changes, including `CREATE DATABASE` and `DROP TABLE` | `destructiveHint` | Yes |

All four tools exist on every backend. Which [object kinds](/tools/objects#kinds) `objects` offers depends on the backend: SQLite has no functions, procedures, or databases, and only PostgreSQL has materialized views.

Pinning a database with `database.name` / `DBMCP_DB_NAME` removes the `database` parameter from every tool and `kind: "database"` from `objects` on MySQL, MariaDB, and PostgreSQL: the server then works with that one database only.
