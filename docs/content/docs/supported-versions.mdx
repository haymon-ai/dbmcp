## Tiers

| Tier | Covers | Promise |
|------|--------|---------|
| **Supported** | Versions in the rule below that have green CI | Tested in CI, bugs fixed, [column-rule](/privacy/rules) guarantees claimed |
| **Best effort** | End-of-life versions; upstream versions not yet Supported (pre-releases, new releases whose CI isn't green yet); Amazon RDS, Google Cloud SQL, and Azure Database Flexible Server when running a Supported version | Issues accepted, not tested, column-rule guarantees not claimed |
| **Unsupported** | Forks and re-implementations, such as Aurora, TiDB, Vitess/PlanetScale, CockroachDB, YugabyteDB | No promise |

## Rule

- **PostgreSQL**: every major version the PostgreSQL project supports.
- **MySQL**: every LTS release in Premier Support (not Extended Support), plus the current Innovation release.
- **MariaDB**: every LTS release with community support, plus the current rolling release.
- **SQLite**: the version bundled into the binary.

A version becomes Supported in the first <Dbmcp /> release whose CI is green on it. It leaves Supported in the first release after its upstream end of life.

Today this means PostgreSQL 15 to 19, MySQL 8.4, 9.7, and 26.10, MariaDB 10.11, 11.4, 11.8, 12.3, and 13.0, and SQLite 3.54.

## Versions

| Backend | Supported | Best effort |
|---------|-----------|-------------|
| PostgreSQL | 15, 16, 17, 18, 19 | 14 and older (end of life); betas and release candidates |
| MySQL | 8.4, 9.7, 26.10 (Innovation) | 8.0 and older (end of life); earlier Innovation releases; previews |
| MariaDB | 10.11, 11.4, 11.8, 12.3, 13.0 (rolling) | 10.6 and older (end of life); earlier short-term and rolling releases; previews |
| SQLite | 3.54.1 (bundled) | — |

Every integration test suite runs against every Supported version on every pull request.

## Services

| Service | Tier | Notes |
|---------|------|-------|
| Amazon RDS | Best effort | When running a Supported version |
| Google Cloud SQL | Best effort | When running a Supported version |
| Azure Database Flexible Server | Best effort | When running a Supported version |
| Forks and re-implementations, such as Aurora, TiDB, Vitess/PlanetScale, CockroachDB, YugabyteDB | Unsupported | Wire-compatible, but catalogs and behaviour differ |

## Other versions

<Dbmcp /> never refuses a server because of its version. When the server is outside Supported, it logs one `WARN` line per process, when the first database connection opens, in every [privacy mode](/privacy#modes). While [column rules](/privacy/rules) exist, the line adds that column-rule guarantees are not claimed. A Supported server logs nothing.

The logged messages look, for example, like this:

| Server | Logged |
|--------|--------|
| A detected fork | `server is Aurora MySQL, an Unsupported fork` |
| Newer than tested | `MySQL 27.4 is newer than the versions tested (Best effort); latest tested is 26.10` |
| End of life or untested | `PostgreSQL 14 is not Supported (Best effort: end of life or untested); Supported: 15, 16, 17, 18, 19` |
| Any of the above, with column rules | The same text, ending in `; column-rule guarantees not claimed` |
| Supported | Nothing |

Managed services can't be told apart from the upstream server, so they get no warning of their own. When the version can't be read, the check is skipped. On MySQL and MariaDB, a server that doesn't match `database.backend` logs only the [mismatch warning](/features/database#backend-defaults).
