Every MCP client keeps its server list in a different file under a different key. This page has a ready-to-paste entry for each one.

All examples launch dbmcp with `npx -y @haymon-ai/dbmcp`, which needs [Node.js](https://nodejs.org/) 18 or newer and no separate install (see [npm](/docs/installation#npm)). To run Docker or an installed binary instead, see [Docker or installed binary](#docker-or-installed-binary).

The examples connect to MySQL with `DBMCP_DB_BACKEND`, `DBMCP_DB_HOST`, `DBMCP_DB_USER`, `DBMCP_DB_PASSWORD`, and `DBMCP_DB_NAME`. Replace the values with your own; every setting is listed in [Configuration](/docs/configuration). An empty `DBMCP_*` value counts as unset, so a blank value falls back to the default.

## Claude Desktop

- macOS: `~/Library/Application Support/Claude/claude_desktop_config.json`
- Windows: `%APPDATA%\Claude\claude_desktop_config.json`

```json title="claude_desktop_config.json"
{
  "mcpServers": {
    "dbmcp": {
      "command": "npx",
      "args": ["-y", "@haymon-ai/dbmcp"],

        "DBMCP_DB_BACKEND": "mysql",

        "DBMCP_DB_PASSWORD": "secret",
        "DBMCP_DB_NAME": "mydb"
      }
    }
  }
}
```

Quit Claude Desktop completely and start it again to load the change.

## Claude Code

Add the server with `claude mcp add`. Options go before the server name, and the launch command follows `--`:

```bash
claude mcp add --env DBMCP_DB_BACKEND=mysql --env DBMCP_DB_HOST=127.0.0.1 \
  --env DBMCP_DB_USER=root --env DBMCP_DB_PASSWORD=secret --env DBMCP_DB_NAME=mydb \
  --transport stdio --scope user dbmcp -- npx -y @haymon-ai/dbmcp
```

Keep another option, such as `--transport stdio`, between the last `--env` and the name: otherwise `--env` reads the name as another `KEY=value` pair. `--scope` is `local` (default, this project only), `project` (writes `.mcp.json`), or `user` (all projects).

To share the server with your team, commit a `.mcp.json` and let each developer supply the password from their own environment with `${VAR}` expansion:

```json title=".mcp.json"
{
  "mcpServers": {
    "dbmcp": {
      "command": "npx",
      "args": ["-y", "@haymon-ai/dbmcp"],
      "env": {
        "DBMCP_DB_BACKEND": "mysql",
        "DBMCP_DB_USER": "root",
        "DBMCP_DB_PASSWORD": "${DBMCP_DB_PASSWORD}",
        "DBMCP_DB_NAME": "mydb"
      }
    }
  }
}
```

For a server you started with `DBMCP_TRANSPORT=http`:

```bash
claude mcp add --transport http dbmcp http://127.0.0.1:9001/mcp --header "Authorization: Bearer $DBMCP_TOKEN"
```

## Codex

Add the server to `~/.codex/config.toml`, or to `.codex/config.toml` in a trusted project:

```toml title="~/.codex/config.toml"
[mcp_servers.dbmcp]
command = "npx"
args = ["-y", "@haymon-ai/dbmcp"]
env = { DBMCP_DB_BACKEND = "mysql", DBMCP_DB_HOST = "127.0.0.1", DBMCP_DB_USER = "root", DBMCP_DB_NAME = "mydb" }
env_vars = ["DBMCP_DB_PASSWORD"]
```

`env_vars` forwards `DBMCP_DB_PASSWORD` from the environment Codex runs in, so the password stays out of the file. Or add the server from the command line:

```bash
codex mcp add dbmcp --env DBMCP_DB_BACKEND=mysql --env DBMCP_DB_USER=root \
  --env DBMCP_DB_PASSWORD=secret --env DBMCP_DB_NAME=mydb -- npx -y @haymon-ai/dbmcp
```

For a server you started with `DBMCP_TRANSPORT=http`, Codex reads the bearer token from the named environment variable:

```toml title="~/.codex/config.toml"
[mcp_servers.dbmcp]
url = "http://127.0.0.1:9001/mcp"
bearer_token_env_var = "DBMCP_TOKEN"
```

## VS Code

Add the server to `.vscode/mcp.json` in your workspace, or to your user profile with **MCP: Open User Configuration**. VS Code uses `servers`, not `mcpServers`, and prompts for each `${input:...}` value on first start:

```json title=".vscode/mcp.json"
{
  "inputs": [
    {
      "type": "promptString",
      "id": "db-password",
      "description": "Database password",
      "password": true
    }
  ],
  "servers": {
    "dbmcp": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@haymon-ai/dbmcp"],
      "env": {
        "DBMCP_DB_BACKEND": "mysql",
        "DBMCP_DB_HOST": "127.0.0.1",
        "DBMCP_DB_USER": "root",
        "DBMCP_DB_PASSWORD": "${input:db-password}",
        "DBMCP_DB_NAME": "mydb"
      }
    }
  }
}
```

For a server you started with `DBMCP_TRANSPORT=http`:

```json title=".vscode/mcp.json"
{
  "inputs": [
    {
      "type": "promptString",
      "id": "dbmcp-token",
      "description": "dbmcp bearer token",
      "password": true
    }
  ],
  "servers": {
    "dbmcp": {
      "type": "http",
      "url": "http://127.0.0.1:9001/mcp",
      "headers": { "Authorization": "Bearer ${input:dbmcp-token}" }
    }
  }
}
```

## Zed

Open your settings with **zed: open settings file** and add the server under `context_servers`:

```json title="settings.json"
{
  "context_servers": {
    "dbmcp": {
      "command": "npx",
      "args": ["-y", "@haymon-ai/dbmcp"],
      "env": {
        "DBMCP_DB_BACKEND": "mysql",
        "DBMCP_DB_HOST": "127.0.0.1",
        "DBMCP_DB_USER": "root",
        "DBMCP_DB_PASSWORD": "secret",
        "DBMCP_DB_NAME": "mydb"
      }
    }
  }
}
```

For a server you started with `DBMCP_TRANSPORT=http`, set `url` and `headers` instead of `command`. Without an `Authorization` header, Zed starts an OAuth flow.

```json title="settings.json"
{
  "context_servers": {
    "dbmcp": {
      "url": "http://127.0.0.1:9001/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

## Gemini CLI

Add the server to `~/.gemini/settings.json` (all projects) or `.gemini/settings.json` (this project):

```json title="~/.gemini/settings.json"
{
  "mcpServers": {
    "dbmcp": {
      "command": "npx",
      "args": ["-y", "@haymon-ai/dbmcp"],
      "env": {
        "DBMCP_DB_BACKEND": "mysql",
        "DBMCP_DB_HOST": "127.0.0.1",
        "DBMCP_DB_USER": "root",
        "DBMCP_DB_PASSWORD": "$DBMCP_DB_PASSWORD",
        "DBMCP_DB_NAME": "mydb"
      }
    }
  }
}
```

<Callout type="warn">
Gemini CLI removes inherited environment variables whose names contain `PASSWORD`, `TOKEN`, `SECRET`, `KEY`, `AUTH`, or `CREDENTIAL` before it starts a server. Set `DBMCP_DB_PASSWORD` in the server's `env`, as above: an exported `DBMCP_DB_PASSWORD` alone never reaches dbmcp.
</Callout>

Or add the server from the command line (`-s user` for all projects):

```bash
gemini mcp add -s user -e DBMCP_DB_BACKEND=mysql -e DBMCP_DB_USER=root \
  -e DBMCP_DB_PASSWORD=secret -e DBMCP_DB_NAME=mydb dbmcp npx -y @haymon-ai/dbmcp
```

For a server you started with `DBMCP_TRANSPORT=http`, use `httpUrl` (`url` means SSE in Gemini CLI):

```json title="~/.gemini/settings.json"
{
  "mcpServers": {
    "dbmcp": {
      "httpUrl": "http://127.0.0.1:9001/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

## Goose

Run `goose configure` and choose **Add Extension → Command-line Extension**, with `npx -y @haymon-ai/dbmcp` as the command. Or edit `~/.config/goose/config.yaml` (Windows: `%APPDATA%\Block\goose\config\config.yaml`):

```yaml title="~/.config/goose/config.yaml"
extensions:
  dbmcp:
    type: stdio
    name: dbmcp
    enabled: true
    cmd: npx
    args: ["-y", "@haymon-ai/dbmcp"]
    envs:
      DBMCP_DB_BACKEND: mysql
      DBMCP_DB_HOST: 127.0.0.1
      DBMCP_DB_USER: root
      DBMCP_DB_PASSWORD: secret
      DBMCP_DB_NAME: mydb
    timeout: 300
```

## Docker or installed binary

Every example above works with another launcher: change only `command` and `args`, and keep `env`.

With the binary from the [install script](/docs/installation#quick-install-recommended) on your `PATH`:

```json
{
  "command": "dbmcp",
  "args": []
}
```

With [Docker](/docs/installation#docker), pass each variable through with `-e NAME` (no value: Docker copies it from the `env` block). Use `host.docker.internal` to reach a database on your machine:

```json
{
  "command": "docker",
  "args": [
    "run", "-i", "--rm",
    "-e", "DBMCP_DB_BACKEND",
    "-e", "DBMCP_DB_HOST",
    "-e", "DBMCP_DB_USER",
    "-e", "DBMCP_DB_PASSWORD",
    "-e", "DBMCP_DB_NAME",
    "ghcr.io/haymon-ai/dbmcp"
  ],
  "env": {
    "DBMCP_DB_BACKEND": "mysql",
    "DBMCP_DB_HOST": "host.docker.internal",
    "DBMCP_DB_USER": "root",
    "DBMCP_DB_PASSWORD": "secret",
    "DBMCP_DB_NAME": "mydb"
  }
}
```

Docker also needs `-i`: without it the container gets no stdin and the client cannot talk to the server.
