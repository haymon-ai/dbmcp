Execute a write SQL query (INSERT, UPDATE, DELETE, CREATE, ALTER, DROP).

<usecase>
Use when:
- Inserting, updating, or deleting rows
- Creating or altering tables, indexes, views, or other schema objects
- Any data modification operation
</usecase>

<when_not_to_use>
- Read-only queries (SELECT, SHOW) → use readQuery
- Query performance analysis → use explainQuery
- Creating/dropping entire databases → use createDatabase or dropDatabase
- Switching database context (USE is rejected) → pass the `database` argument
</when_not_to_use>

<examples>
✓ "INSERT INTO users (name, email) VALUES ('Alice', 'alice@example.com')"
✓ "UPDATE orders SET status = 'shipped' WHERE id = 42"
✓ "CREATE TABLE logs (id INT PRIMARY KEY, message TEXT)"
✗ "SELECT * FROM users" → use readQuery
</examples>

<what_it_returns>
An object with:
- `rows`: rows returned by the statement (e.g. `INSERT ... RETURNING` on MariaDB), each keyed by column name; empty for most writes.
- `rowsAffected`: rows inserted, updated, or deleted. `UPDATE` counts matched rows, even when values did not change. `0` for schema changes.
- `lastInsertId`: the `AUTO_INCREMENT` id generated by an `INSERT` (the first one for a multi-row insert). Absent when none was generated.

No follow-up `SELECT` is needed to confirm a write.

Long string values are cut and end in `…[truncated, N chars total]`, and rows past the response size cap are dropped; when either happens the response carries `truncated: true` and a `hint`.
</what_it_returns>
